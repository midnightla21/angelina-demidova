# Публикация на VPS

Проект экспортируется в статические HTML, CSS, JavaScript и изображения. В production эти файлы обслуживает Caddy. GitHub хранит исходники; автоматическая доставка изменений на сервер в этом репозитории не настроена.

## Подготовка выпуска

1. Установите зависимости и подготовьте локальный `hosting.json` по README.
2. Закоммитьте изменения и выполните `npm run build`.
3. Запустите собранную версию командой `npm run start -- --port 3001`.
4. В другом терминале выполните `node --test tests/locales.test.mjs`.
5. Выполните `node scripts/export-vps.mjs`, пока этот же production-сервер работает.

Результат находится в новой папке `outputs/vps-…/`. Не смешивайте HTML из одного выпуска с клиентскими файлами другого: они содержат связанные идентификаторы React и имена ресурсов.

## Размещение

1. На своём сервере установите Caddy и создайте отдельную папку нового выпуска.
2. Загрузите туда содержимое экспортированной папки `public/` целиком.
3. Проверьте, что пользователь Caddy может читать файлы.
4. Настройте путь `/srv/angelina/current` на папку `public/` выбранного выпуска. Экспортируемый Caddyfile использует этот путь.
5. Проверьте конфигурацию Caddy и примените её штатной перезагрузкой конфигурации. На сервере с другими сайтами добавляйте блок этого сайта к существующей конфигурации.

Экспортёр создаёт `Caddyfile` для `angelina-demidova.ru` и вариант `Caddyfile.staging` для HTTP. Они включают маршруты языков, обработку React payload, сжатие, кэширование ресурсов, редирект `/ru` и страницу 404.

Для другого домена нужно согласованно изменить адрес в экспортёре, метаданных, sitemap, robots.txt и проверках.

## HTTPS и проверка

Домен должен указывать на ваш сервер; порты 80 и 443 должны быть доступны извне. Caddy запрашивает и продлевает сертификат автоматически. Его рабочие данные, включая сертификаты, должны сохраняться между перезапусками.

После публикации:

```sh
SITE_TEST_ORIGIN=https://angelina-demidova.ru node --test tests/locales.test.mjs
```

Дополнительно проверьте перенаправление HTTP на HTTPS. Сохраняйте предыдущую папку выпуска для отката. Доступы к VPS, приватные ключи и пароли храните отдельно от репозитория.
